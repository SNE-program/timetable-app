# 角色包规范（v1）

> 面向想自己做角色包的人。同一份内容在应用内也有：**说明书 → 角色 → 怎么做一个角色包**。
> 应用内的那份是给人看的，这份是给人查的。

## 0. 一句话

角色包是一个 JSON 文件，描述"显示什么图、怎么动"，**不带任何代码**。
应用只负责把它画出来 —— 它能闯的最大的祸就是不好看。

## 1. 为什么这么设计

| 决定 | 理由 |
| --- | --- |
| **纯数据，无可执行内容** | 应用里没有 eval、没有远程代码、没有第三方 SDK。开一个能执行代码的口子，"无广告无追踪"就从可验证的事实变成口头承诺 |
| **不内置任何角色** | 不喜欢屏幕上多个活物的人应该永远看不到这个功能；另外内置角色还牵扯素材版权 |
| **只支持 WebView 原生能播的素材** | Live2D / Rive / Spine / Lottie 每一个都要求引入运行时，为它们换掉"产物里没有第三方代码"这条底线不值 |
| **素材内嵌为 data URI** | 应用不联网。src 写成 http 链接会被直接拒绝 |
| **素材存资产库而不是 localStorage** | 一张立绘一两 MB，localStorage 只有约 5 MB 配额。配额一满，**课表数据本身**就写不进去了 |

## 2. 文件形态

~~~json
{
  "format": "timetable-mascot",
  "version": 1,
  "exportedAt": "2026-09-11T00:00:00.000Z",
  "assets": [{ "state": "idle", "kind": "still", "mime": "image/png", "bytes": 204800 }],
  "mascot": { "...": "真正的角色数据在这里" }
}
~~~

外层是"包文件"，`assets` 只是一份便于人查看的清单。
**只有 `mascot` 字段是必需的** —— 直接给一个裸的 `mascot` 对象也能导入
（区分方式是看有没有 `mascot` 字段，不是看 `format`）。
手搓最小包时不必套这层壳。

## 3. 字段

| 字段 | 必填 | 取值 | 说明 |
| --- | --- | --- | --- |
| `format` | 是 | 固定 `timetable-mascot` | 写错会明确报错 |
| `version` | 否 | 目前 1 | 高于当前支持的版本只给提示，不拒绝 |
| `id` | 否 | 字符串 | 缺省自动生成 |
| `name` / `author` / `description` | 否 | 字符串 | 显示用 |
| `height` | 否 | 56–320 | 建议显示高度，用户还能再调 |
| `states.idle` | **是** | 素材对象 | 唯一必填的状态；缺了整包拒绝 |
| `states.react` | 否 | 素材对象 | 被点一下（约 0.9 秒） |
| `states.sleep` | 否 | 素材对象 | 3 分钟没人理时 |
| `states.drag` | 否 | 素材对象 | 拖动过程中 |
| `motion.breathe` | 否 | 0–0.08 | 呼吸幅度（纵向缩放），默认 0.02 |
| `motion.bob` | 否 | 0–0.06 | 上下浮动（相对高度），默认 0.01 |
| `motion.sway` | 否 | 0–8 | 左右摇摆度数，默认 0 |
| `interactive.click` | 否 | 布尔 | 是否响应点击，默认 true |
| `interactive.drag` | 否 | 布尔 | 能否拖动，默认 true |
| `shadow` | 否 | 布尔 | 脚下投一小团阴影，默认 true |
| `anchor.x` / `anchor.y` | 否 | 0–1 | 贴边锚点，默认 (0.5, 1) 即底部居中 |

缺失的状态**自动退回 `idle`**，不是错误 —— "只放一张图"必须是一条能走通的路径。

## 4. 素材对象

| `kind` | 含义 | 额外字段 |
| --- | --- | --- |
| `still` | 一张静态图 | 无。呼吸/浮动由 `motion` 补上 |
| `animated` | 动图（animated WebP / APNG / GIF） | 无。浏览器自己播 |
| `sheet`（来自视频） | 视频抽帧拼成的雪碧图，见第 12 节 | `cols`、`rows`、`fps` |
| `sheet` | 逐帧雪碧图 | `cols`、`rows`（1–32）、`fps`（1–24） |

`sheet` 的 `cols × rows = 1` 时会**降级成 `still` 并给一条提示**，而不是报错。

## 5. 校验与降级总表

| 情况 | 行为 |
| --- | --- |
| `format` 不是 `timetable-mascot` | 拒绝，明确说明期望值 |
| 缺 `states.idle` | 拒绝，明确说缺的是哪一项 |
| 某个状态的 `src` 不是内嵌图片（例如 http 链接） | **跳过那个状态**并提示，其余照常可用 |
| `cols × rows = 1` | 降级成静态图并提示 |
| 数值越界（height 9999、breathe 99…） | 收敛到合法区间，不报错 |
| `src` 是 `asset:xxx` | 校验放行（本机存盘后的形态）；**导出时会自动去掉**，手写没有意义 |

## 6. 制作流程（推荐路径）

不要去手工折腾 base64：

1. 应用内「用一张图当角色」把想要的那张立绘导入 —— 应用会压到 1024 px 长边并转成 WebP（保留透明通道）；
2. 点「导出角色包」，你会拿到一份**已经内嵌好图片**的 JSON，这就是模板；
3. 用文本编辑器改：加状态、调 `motion` 数字；
4. 「导入角色包」选这个文件覆盖回去。

## 7. 素材准备建议

- **尺寸**：按显示高度的 2 倍准备（显示 140 px 就做 280 px 高），长边不超过 1024；
- **透明背景**：PNG 或 WebP。白底图在深色主题上会变成一块白方块；
- **动图**：多数绘画/剪辑工具都能导出 animated WebP 或 APNG，两者都比 GIF 小且支持透明；
- **点到反应**建议 0.5–1.5 秒，太长会显得迟钝；
- **打瞌睡**适合用慢速逐帧图，动作比待机更小。

## 8. 运行时的行为约定

状态机分**两层**：外层是**相位**（`idle` / `react` / `sleep` / `drag`，语义只有四个、切换条件都是硬的），
内层是**微动作**（8 种，每次做什么、做多久、快慢幅度多少都是当场掷出来的）。
随机源由调用方注入（生产用 `Math.random`，单测传固定种子），所以状态机本身是纯函数、可复现。

| 时机 | 行为 |
| --- | --- |
| 待机 | 八种微动作轮换：呼吸 / 抖一下 / 伸懒腰 / 抬起头 / 打哈欠 / 来回走走 / **东张西望** / **点头** |
| 待机时的方向性 | 三条通道（呼吸缩放 / 上下浮动 / 左右摇摆）各有配比：张望偏左右、点头偏上下 —— 不是同一个动作换速度 |
| 眨眼 | 间隔**真随机** 2.6–6.2 秒（不是固定节拍），只有静态图会眨眼 |
| 点一下 | 进 `react` 约 0.9 秒，随机播四种反应之一；从睡眠中被点醒，反应完回到睡眠 |
| **没人点也会自己动** | 动作切换时按概率自发播一次性动画（醒着 0.28 / 睡着 0.22），只从蹦一下 / 晃两下 / 凑过来看里挑（`startle` 不参与，否则像出 bug）|
| 3 分钟无人交互 | 进 `sleep`，动画周期放慢 1.6 倍 |
| **睡着之后（打盹循环）** | 每隔 **45–150 秒**醒一小段（**4–14 秒**），那一段走**正常动作池**（含走动），结束时打一个哈欠睡回去 |
| 睡着时的动作池 | 单独一套（呼吸 / 翻身 / 打哈欠为主），**"走走"权重恒为 0** —— 睡着了还踱步就不叫睡了 |
| 半醒那一段的精神头 | 用 `WAKING_ENERGY = 0.62` 兜底：长时间没人理时能量会掉到 0.2 上下，而"走走"的权重在低能量时几乎是 0，不兜底的话"醒了"等于没醒 |
| 拖动中 | 进 `drag`，自走动画全部停止（手指按着还在晃会很难对准）；被抓起来等于醒了，打盹循环整个清掉 |
| 任何接触（点 / 拖 / 长按） | 清空打盹循环，睡意从头计时 |
| 系统「减弱动态效果」开启 | 所有动画归零，只静态显示 |
| 页面切到后台 | 所有计时器停止 |
| 临近上课（10 分钟内） | 每 20 秒最多招手一次（借用 `react`） |
| 深夜 / 今天的课上完又入夜 | 打瞌睡的阈值从 3 分钟缩到 45 秒 |
| 长按 600ms | 弹快捷菜单（收起来 / 回到默认位置 / 打开外观 / 看教学） |
| 转屏、分屏、软键盘 | 重新按安全区钳制一次，越界的位置会被悄悄纠正 |
| 位置 | 锚点存归一化坐标；渲染时按**实测的顶栏下沿与标签栏上沿**钳制，拖不出可用区 |

## 9. 两条给实现者的硬约束

1. **浮层不参与布局**：`position: fixed`。一旦进文档流，320 px 窄屏的排版立刻会变；
2. **不挡可点控件**：外层 `pointer-events: none`，只有角色本体 `auto`。
   布局自检里有一条专门测这个（`MASCOT … 遮挡可点控件=N`），要求为 0。

> 已知的残留问题：角色所在位置若正好压住某个控件，那**角色本体覆盖的那一小块**是点不到的
> （其它区域不受影响）。用户可以拖走、长按收起来 —— 首次导入的提示里会说明可以拖动。
> 自检里的 `MASCOT … 遮挡可点控件=N` 会把这类重叠报出来（外观页在 320px 下目前是 1）。

## 10. 素材的回收

换角色或移除角色时，按 **"旧包用到的 key 减去新包用到的 key"** 精确删除旧素材。

刻意**不做全局扫描式清理**：那需要一个正确的 keep 列表（主题 + 课程配图 + 角色），
而 keep 列表一旦算错（比如在素材已还原成 data URI 之后去收集引用），删掉的就是还在用的图。
差集法的输入是确定的，错不了。

## 11. 视频素材（webm / mp4）

二游的动图素材大量是 **webm**。它是视频不是图片：`<img>` 解不了，
原有的图片管线第一行就把它拒了。所以有一条单独的管线 —— **抽帧拼成逐帧雪碧图**。

选这条路而不是"直接播视频"，是因为：

1. 不用新增素材类型，资产库、导出、编辑器全都不用改；
2. 不依赖 video 的自动播放策略，也不会在桌面上同时跑一堆解码器；
3. 抽完就是一坨确定的像素，帧率、循环、暂停都由我们自己说了算。

排版规则（`planSheet`，纯函数，14 个用例）：

| 项 | 规则 |
| --- | --- |
| 帧率 | 默认 12，夹在 4–24 |
| 帧数 | `时长 × 帧率`，夹在 2–48 |
| 排布 | 最多 8 列，行数向上取整 |
| 单格尺寸 | 高度不超过 480（角色最大显示 320px，3.5 倍屏约 1120 物理像素，够用且省体积） |
| 整图上限 | 最长边 2048，超了就把单格等比缩小 |
| 采样点 | 取每一小段的**中点** —— 很多视频开头几帧是黑的，取起点会得到一格全黑 |

**已知限制**：带透明通道的 webm 是否保留透明，取决于系统解码器，
不同机型表现不一样。出现黑底时改用 PNG / WebP 动图或 APNG。

## 12. 自检入口

| 参数 | 用途 |
| --- | --- |
| `?mascot=1` | 静态图角色 |
| `?mascot=2` | 逐帧雪碧图角色（4×2 网格，验证缩放与偏移） |
| `?mascot=3` | 动图角色（动画 SVG，走 `<img>` 原生播放那条路） |
| `?mascot=4` / `?mascot=5` | 半满网格（8×2 只画 9 帧）：带 / 不带 `frames` 的对比，验证"不会播到空格子" |
| `?mascot=6` | **待机 / 走动 / 睡着三张不同颜色的素材** —— 用来按 `data-state` 与像素确认"走动时换的是哪一张" |
| `?doze=<秒>` + `?behavecheck=<秒>` | **把打盹循环压短**（多久算睡着 = 参数秒数，睡 / 醒两段同比例缩短），否则一条 60 秒的自检最多等到一轮。自检结果里会报 `睡N次 半醒N轮` 与相位序列 |

三条路径各自对应一种渲染分支。**加这个入口是值得的**：第一次跑 `?mascot=2` 就报出
`MASCOT 0x140` —— 逐帧图的容器宽度塌成了 0（`background-image` 的元素没有固有尺寸，
`width:auto` 会算成 0），也就是那个模式下角色根本看不见。
