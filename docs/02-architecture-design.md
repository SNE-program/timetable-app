# 课表 App 总体设计（v0.1 草案）

配套文档：[竞品调研](./01-competitor-research.md) · [核心数据模型](./03-core-data-model.ts)

---

## 0. 一句话定位

**一个本地优先、无广告、界面可 DIY、能力可插拔的课表与上课提醒 App。**
核心是一套可测试的"时间引擎"；AI 与插件都是可替换的上层，从第一天就被预留接口，但删掉它们之后 App 依然完整可用。

---

## 1. 设计原则（不可妥协的六条）

| 编号 | 原则 | 含义 |
| --- | --- | --- |
| P1 | **本地优先** | 断网可用，数据默认只在本机；云同步是可选项而非前提 |
| P2 | **核心纯净** | core 包是纯函数 + 纯数据：零 UI、零平台 API、零网络依赖，可 100% 单元测试 |
| P3 | **AI 与插件皆为可选层** | 卸载全部插件、关掉 AI，App 依然是完整的课表工具 |
| P4 | **数据模型优先于界面** | 先把"单双周 / 连堂 / 调停补课 / 多作息 / 多校区"表达清楚，UI 只是视图 |
| P5 | **一切可 DIY** | 颜色、圆角、字体、卡片布局、通知文案都能改；主题可导出分享 |
| P6 | **可逆** | 任何导入或 AI 写入都先出 diff 预览、用户确认、可一键撤销 |

## 3. 数据模型（设计的重中之重）

完整类型见 [03-core-data-model.ts](./03-core-data-model.ts)，这里只讲四个关键决策。

### 3.1 周次用显式数组，不用"单双周"枚举

大多数 App 把周次硬编码成"每周 / 单周 / 双周"，一遇到 [1,2,3,7,8] 这种实训周就崩。
我们用 **WeekSelector** 四选一：all / range / list / stepped。表达能力覆盖真实教务数据，且实现成本几乎不变。

### 3.2 节次与钟点解耦

课程数据里**只存"第 3-4 节"，不存"10:00-11:35"**。具体钟点由 **PeriodScheme（作息方案）** 决定。
收益：
- 冬夏令时作息切换 → 改一个方案，全部课程自动跟着变；
- 多校区不同作息 → 同一张课表正常显示；
- 学校临时调整作息 → 用户改一次即可，不用重录课表。

### 3.3 例外用 Override 叠加

停课、补课、换教室、换时间，都表达为"**对某一天某一次课的补丁**"，绝不修改原始课表。
收益：撤销容易、审计清晰、AI 出错也不会污染原始数据、能回答"这门课一共被调过几次"。

### 3.4 时间轴可以无限延伸

**课表存的是「重复规则」，不是「具体事件」。** 一门课只存 `{dayOfWeek, periodStart, periodEnd, weeks}`，而不是把每周一都生成一条记录。
由此得到三个结论：

| 问题 | 答案 |
| --- | --- |
| 存一年和存十年，存储差多少？ | **一样**。规则数量不变 |
| 翻到第 500 周会不会变慢？ | **不会**。`expandDay` 只做 O(课程数) 的规则匹配，与时间轴长度无关 |
| 有数值上限吗？ | **没有**。JS Date 可表示 ±27 万年，整数在 2^53 内精确 |

要做到这一点，有两条硬约束：

1. **判断周次必须用 O(1) 谓词 `weekMatches(sel, week, limit)`，绝不能物化数组。**
   早期实现用 `weeksOf(...).includes(w)`，它会把整个学期展开成数组 —— 学期一无限就会死循环。
   `weeksOf()` 仅保留给界面展示，且强制收敛到 `MAX_ENUM_WEEKS`。
2. **UI 必须虚拟化。** 周次选择条只渲染当前周前后各 7 周，而不是渲染 N 个胶囊。

**产品语义要分清两件事**（这是设计决策，不是技术限制）：

- **时间轴无限**：可以翻到任意日期 —— 无条件支持。
- **课程无限重复**：这门课永远每周一上 —— **不设为默认**。默认跟随学期结束，用户显式勾选「不设结束」才无限。
  否则毕业十年后，你的高数还会在周一早上八点响。

提醒系统不受影响：它本来就是 7 天滚动窗口，**绝不能**因为课无限就预排无限个闹钟（Android 有约 500 个 alarm 的硬限制）。

### 3.5 一切写入都走 ChangeSet

**这是为 AI 和插件埋的最重要的一根管线。**
AI 和插件都**不能直接写数据库**，只能产出一个 ChangeSet（新增/修改/删除的列表），由 core 校验、生成 ChangePreview（含冲突检测）、交给用户确认，之后才落库，且整体可回滚。

这条约束同时解决了三个问题：AI 幻觉污染数据、插件越权、导入出错无法挽回。

## 4. 时间引擎（核心中的核心）

**输入**：Term + PeriodScheme[] + Course[] + Session[] + Override[]
**输出**：ConcreteEvent[]（某一周 / 某一天真正会发生的事件流）

处理顺序：
1. 周次解析：WeekSelector → 该学期内的具体日期集合
2. 日期映射：dayOfWeek + week → 真实日期（跨月、跨年边界要正确）
3. 应用 Override：cancel 剔除、reschedule 改期、roomChange 改地点
4. 节次映射：periodStart/End → 具体钟点（依赖 PeriodScheme）
5. 排序与去重
6. 派生计算：下一节课、空闲时段、冲突检测

**工程要求**
- 纯函数，同样输入必得同样输出；用快照测试锁死行为；
- 按 (termId, weekIndex) 记忆化，避免 UI 频繁重算；
- 边界用例必须覆盖：跨天连堂、跨年学期、闰年、时区、作息切换周、调课后与原课冲突。

这是提醒、今日页、小组件、AI 问答共同的地基 —— **地基写扎实，上层才能随便换。**

## 5. 提醒子系统

### 5.1 规则分层（优先级由具体到宽泛）
Session 级 > Course 级 > Term 级 > 全局默认。
每条规则支持**多个提前量**（例如课前 30 分钟提醒准备、课前 5 分钟提醒出发），支持限定生效周次。

### 5.2 四类提醒
1. **课前提醒**：默认提前 15 分钟，按课程可覆盖；
2. **明日课表摘要**：前一日 21:00，"明天 4 节课，8:00 早八 A301，记得带实验报告"；
3. **变更提醒**：检测到调课/停课/换教室时即时推送；
4. **冲突预警**：连续两节课在不同楼且间隔过短时提示。

### 5.3 渠道抽象（Channel）
system（本地通知，主力）/ widget（小组件）/ desktop（桌面悬浮）/ ics（日历订阅）/ webhook（Bark、Server 酱、邮件、企业微信）/ 插件自定义。

### 5.4 可靠性设计（这一块最容易做烂）
- **本地通知为主**，不依赖网络与服务端；离线也准；
- **通知指纹** fingerprint = hash(sessionId | date | offset | channel) 落库，杜绝重启/重装/多端重复提醒；
- **错过补偿**：App 启动时回扫过去 10 分钟内本应触发但未触发的提醒，补发一条；
- **系统事件监听**：时区变更、系统时间修改、夏令时切换 → 重排全部待发通知；
- **静默时段**：可选，夜间不打扰但保留次日摘要。

## 6. 主题与 DIY 系统（本项目最直观的差异化）

### 6.1 三层结构
1. **Design Token（原子）**：颜色、字号、圆角、间距、阴影、动效时长；
2. **语义样式（组件级）**：卡片、时间轴、节次轴、周次条分别取哪些 token；
3. **布局模板（结构级）**：网格 / 列表 / 时间轴 / 极简四种课表布局。

### 6.2 主题包 = 纯数据

~~~
theme.json
{
  "meta":   { "id": "paper", "name": "纸质手账", "author": "...", "version": "1.0.0" },
  "tokens": { "color.bg": "#FAF7F0", "radius.card": 4, "font.family": "serif" },
  "components": { "courseCard": { "style": "flat", "showTeacher": false } },
  "layout": { "type": "grid", "periodAxisWidth": 44 }
}
~~~

**主题是数据而不是代码**：安全、可分享、可热切换、可社区流通。
高级用户可写受限的 CSS 变量覆盖，但**禁止任意 JS**（防止主题变成后门）。

### 6.2.1 图片是一等公民

纯色不是唯一选择。这些位置都可以放图片：

| 位置 | 说明 |
| --- | --- |
| 应用背景 | 全局壁纸，模糊度与压暗程度可调 |
| 课程卡片 | 每门课可以有自己的配图，卡片叠加压暗层保证文字可读 |
| 今日「下一节课」大卡 | 复用课程配图，做成沉浸式头图 |
| 桌面小组件 | 沿用主题背景 |
| 空状态插图 | 主题包可携带 |

内置 **10 张程序化生成的壁纸**（图纸 / 碳纤维 / 点阵 / 极光 / 霓虹 / 纸纹 / 网格纸 / 樱花 / 深海 / 水墨），全部由 SVG 运行时生成，**不依赖任何网络资源**，离线可用且可无限调参。

用户上传的图片会自动等比缩放（长边 ≤ 1920px）并转成 WebP 压缩后入库，避免把几 MB 原图塞进本地存储。

### 6.2.2 主题包：导入导出，图片一起走

主题导出为单文件 **.timetheme.json**，**图片以 data URI 内嵌其中**，是一份自包含的配置：发给同学、拖进 App 即可用，不需要另外传图。支持按钮选择与全屏拖拽两种导入方式。

导入时逐字段校验与归一化（非法色值回退、数值夹紧、缺图降级为无壁纸），保证别人给的主题不会把界面搞坏。完整规范见 [主题包规范](./05-theme-package-spec.md)。

### 6.3 DIY 面板
- 左侧实时预览，改一个 token 立刻看到效果；
- **自动色板**：用户选一个主色，自动生成 12 色课程色板（统一饱和度与明度，保证深浅色下都好看）；
- 一键导出 / 导入 / 生成分享码；
- 内置 7 套主题：极简黑白、毛玻璃、纸质手账、深色霓虹、樱花、网格纸、深海。

### 6.4 视觉规范（工业化 · 参考主流大厂设计语言）

**一句话**：小圆角、实色描边分层、弱阴影、紧凑栅格、克制的颜色。

| 维度 | 取值 | 说明 |
| --- | --- | --- |
| 圆角 | 卡片 4 / 面板 6 / 按钮 4 / 标签 3 / 胶囊 999 | **只有标签允许全圆**，卡片一律接近直角 |
| 分层方式 | **1px 实色描边**；阴影仅 0 1px 2px rgba(0,0,0,.04) | 层次交给线，不交给影子 |
| 描边色 | 浅色 #DDDEE0，深色由底色推导 | 用实色而非半透明，保证 1px 线在任何背景上都干净 |
| 字号阶梯 | 11 / 12 / 13.5 / 16 / 20 / 28，行高 1.5 | 比常规小一档，信息密度优先 |
| 数字 | 全部 tabular-nums | 时间列必须能对齐 |
| 栅格 | 8pt；间距 4 / 8 / 12 / 16 / 24 / 32 | |
| 密度 | 行高 紧凑 56 / 标准 68 / 宽松 84 | 默认一屏尽量看到一整天 |
| 动效 | 140ms，cubic-bezier(.2,.8,.2,1) | 比常见的 200–300ms 更干脆 |
| 强调色 | 默认 #1677FF（Ant Design 蓝） | 主色只用在选中态、进度条、左侧色条 |
| 课程卡 | 默认「色条」：白底 + 3px 左色条 + 1px 描边 | **颜色只出现在色条上**，一屏扫读更快 |
| 状态反馈 | 选中 = 填充主色；悬停 = 描边加深 | 不用位移与放大 |
| 对比度 | 正文 ≥ 4.5:1；提供色盲友好色板与字号缩放 | |

**参考对象**：Ant Design 5（#1677FF、圆角 2/4/6/8、实色描边）、Arco Design、TDesign（#0052D9、圆角 3/6/9），以及主流中后台「左侧色条 + 白底卡」的信息表达方式。

**内置主题 8 套**：工作台（默认）、石墨、终端、腾讯蓝、工业橙、蓝图、暗夜、樱花 —— 前 6 套走工业化路线，后 2 套保留人格化对照。

## 7. 插件系统（可扩展性的落地形式）

### 7.1 五类扩展点

| 类型 | 作用 | 示例 |
| --- | --- | --- |
| **Importer** | 把外部数据变成课表 | ICS 文件、Excel、教务页面文本、课表截图、分享码、他校插件适配器 |
| **Widget** | 新的展示形态 | 今日卡片、下一节课倒计时、桌面悬浮窗、手表视图 |
| **Channel** | 新的通知渠道 | Bark、Telegram、邮件、智能音箱、宿舍灯 |
| **Theme** | 主题包 | 用户自制主题、社区主题 |
| **AIProvider** | 新的模型接入 | OpenAI 兼容端点、DeepSeek、本地 Ollama、自建服务 |

### 7.2 权限模型
插件在 manifest 中声明权限：schedule:read / schedule:write / notify / network / calendar / files / ai。
安装时用**人话**展示："此插件可以：读取你的课表、发送通知、访问网络"。

### 7.3 安全边界
- 插件通过**宿主 API 能力令牌**访问数据，拿不到数据库句柄；
- schedule:write 也必须走 ChangeSet + 用户确认；
- v1 实现为同进程 + 权限包装（简单、够用）；v2 可升级到 Worker / 独立进程沙箱。

### 7.4 事件钩子
onScheduleChanged（只读通知）、beforeNotify（可改写通知文案）、resolveNextEvent（可覆盖"下一节课"的判定，例如把自习也算进去）、registerCommand（给 App 加命令）。

## 8. AI 子系统（为未来预留，现在就把地基埋好）

### 8.1 能力分层（按落地难度排序，逐层实现）

| 层级 | 能力 | 价值 | 难度 |
| --- | --- | --- | --- |
| **L0** | 无 AI，核心功能完整 | 保底 | — |
| **L1** | 截图 / PDF / 教务页面文本 → 结构化课表 | ★★★ 最高频刚需 | 低 |
| **L2** | 自然语言录入与修改："每周二 3-4 节高数，A301，1-16 周" | ★★★ | 低 |
| **L3** | 日程问答："我明天几点有空""下周三要去哪几栋楼" | ★★ | 中 |
| **L4** | 学习计划、DDL 汇总、复习节奏建议 | ★★ | 中 |
| **L5** | 选课冲突检查与建议（开学季高价值） | ★★ | 中 |
| **L6** | Agent：把"帮我腾出周四下午"变成一串受控操作 | ★ | 高 |

### 8.2 抽象契约
- **AIProvider**：声明 capabilities（text / vision / json / tools / streaming），实现 chat 与可选 stream；实现可换，App 不绑定任何厂商；
- **AITask**：任何 AI 能力都必须走同一条流水线 ——
  buildPrompt → 模型返回 → **JSON Schema 校验** → 语义校验 → 转 ChangeSet → **diff 预览** → 用户确认 → 落库。
- **受控工具（Tool Calling）**：AI 只能调用宿主提供的工具（query_schedule、propose_create_session…），**工具的执行方是核心，不是模型**。

### 8.3 六条防翻车约束
1. **AI 永不直接写库**，只产出 ChangeSet；
2. **结构化输出必须过 Schema**，校验失败就报错重试（最多一次），绝不猜测补全；
3. **引用可追溯**：AI 提到的每一节课都能点回原始实体，幻觉无处藏身；
4. **隐私分层**：默认不发送任何数据；发送前可脱敏（教师姓名、学号、个人备注）；发送前让用户看到"将要发送的内容"；
5. **成本可控**：token 预算、结果缓存（同样的截图不重复识别）、可完全关闭；
6. **离线降级**：无网络时隐藏 AI 入口，不弹错误、不阻塞核心流程。

### 8.4 现在就必须做的四件预留（即使暂时不实现 AI）
1. 所有写入走 **ChangeSet**（第 3.4 节）→ AI 天然具备预览与撤销能力；
2. 实体保留 **source 与 confidence** 字段 → 能区分人录的还是 AI 猜的，UI 可高亮"待确认"；
3. 提供 **timetableToPromptText()**：把课表序列化成模型友好的紧凑文本，是 L2/L3 的公共输入；
4. 建立 **packages/ai 目录与类型契约**，即使先给一个 MockProvider。

> 这四条的成本很低，但如果不现在做，将来接 AI 时要重写半个核心。

## 9. UI / UX 设计

### 9.1 信息架构
底部四个 Tab：**本周**（课表）/ **今日** / **任务**（作业与 DDL）/ **设置**。
设置内分组：外观 DIY · 导入导出 · 提醒 · 插件 · AI · 数据与隐私。

### 9.2 本周页（主屏）
- 左侧节次轴：显示"第 3 节"与对应钟点；
- 顶部周次胶囊条：1 至 20 周横向滑动，当前周高亮，可一键回本周；
- 课程卡片：圆角 16、按课程色渐变、显示课程名 + 地点 + 教师；非本周的课淡化处理；
- 今日所在列高亮；空档显示淡淡的"空闲"；
- 交互：左右滑动切周、长按拖拽调课、双指缩放切换紧凑/舒适密度。

### 9.3 今日页
顶部"**下一节课**"大卡：倒计时 + 课程名 + 教室 + "还有 12 分钟"；
下方时间轴：时间 → 卡片 → 距开始/结束的剩余时间，已过的课灰化。

### 9.4 课程详情
基本信息、本周安排、全部周次一览、备注与作业、出勤记录、颜色设置、**单独提醒规则**。

### 9.5 快速添加
底部浮动按钮展开四个入口：**拍照识别（AI）** / 手动录入 / 从教务导入 / 分享码。

### 9.6 首次引导
三步：设置学期（起始日期 + 周数 + 作息）→ 导入或手输 → 设置提醒。全程可跳过。

## 10. 技术选型

### 方案 A（推荐）：TypeScript monorepo + Capacitor / Tauri
| 层 | 技术 | 理由 |
| --- | --- | --- |
| 语言 | TypeScript（strict） | 一套类型贯穿核心、UI、插件与 AI 契约 |
| 仓库 | pnpm workspaces + Turborepo | 多包共存、增量构建 |
| 核心 | packages/core（纯 TS） | 无 DOM、无平台 API，测试友好 |
| UI | React + Tailwind + CSS 变量 Token + Framer Motion | **主题即 CSS 变量 → DIY 最彻底** |
| 状态 | Zustand + TanStack Query | 轻量、可预测 |
| 本地库 | SQLite（Drizzle ORM） | 结构化查询、迁移成熟 |
| 移动 | Capacitor 6 + 原生本地通知插件 | 复用 Web 代码，同时拿到原生通知可靠性 |
| 桌面 | Tauri 2 | 体积小，可做悬浮课表（对标 Class Widgets） |
| Web | PWA | 在线查看与主题分享 |
| 测试 | Vitest（core 覆盖率目标 100%）+ Playwright | 时间引擎必须锁死 |
| AI | packages/ai（OpenAI 兼容 / Ollama 适配） | 不绑定厂商 |

**优势**：主题与插件用 Web 技术做，DIY 上限最高、迭代最快、AI 接入生态最全。
**代价**：需为移动端写少量原生桥接（通知、小组件、灵动岛）。

### 方案 B：Flutter
一套代码覆盖全平台，原生性能与小组件生态成熟。
**代价**：主题只能编译期生效，DIY 受限；插件需 Dart 生态；与"用户自己改界面"的目标冲突。

### 方案 C：原生 Kotlin + Swift
提醒与桌面组件最可靠、体验最精致。
**代价**：双倍开发量，与快速迭代冲突。

### 结论
本项目把"**DIY + 插件 + 快速迭代 + 未来接 AI**"放在第一位 → **默认选方案 A**。
同时坚持 P2 原则：**core 写成平台无关**，将来若因提醒可靠性或性能必须切到 Flutter/原生，只需重写 UI 层，核心与数据可原样迁移。

## 12. 路线图

| 里程碑 | 周期 | 交付 | 验收标准 |
| --- | --- | --- | --- |
| **M0 地基** | 1-2 周 | core 数据模型 + 时间引擎 + 手动录入 + 周视图 + 本地提醒 | 单双周/连堂/调课全部正确；core 单测覆盖率 100% |
| **M1 好用** | 2-3 周 | 今日页 + 主题系统 + 6 套内置主题 + DIY 面板 + ICS/JSON 导入导出 + 桌面小组件 | 用户能自己改出一套界面并导出主题 |
| **M2 生态** | 3-4 周 | 插件 SDK + 3 个示例插件（教务导入 / 通知渠道 / 主题包）+ 分享码 | 第三方插件能不改核心就装上并生效 |
| **M3 AI** | 2-3 周 | AIProvider 层 + 截图导入 + 自然语言录入 + 日程问答 | 截图识别结果必须经 diff 确认才入库；关掉 AI 一切正常 |
| **M4 深度** | 持续 | 多端同步、选课冲突建议、Agent、主题社区 | — |

**排序理由**：先把"时间正确 + 提醒可靠"做扎实（M0），再做"好看好改"（M1），再做"能扩展"（M2），最后才是"聪明"（M3）。反过来做的话，AI 与插件会建在流沙上。

## 13. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 教务系统千校千面、改版频繁 | 导入功能持续腐烂 | **不做内置爬虫**；走 ICS / 文件 / 截图 / 分享码 + 社区 Importer 插件 |
| 爬虫与 SSO 的合规风险 | 法律与封号风险 | 只处理用户主动提供的页面内容与文件，不做批量抓取与账号代管 |
| iOS 后台通知限制 | 提醒不准时 | 全部使用原生本地通知预排 + 启动时补偿 + 时区变更重排 |
| AI 幻觉污染课表 | 数据不可信 | ChangeSet + Schema 校验 + diff 确认 + 一键回滚 + 可追溯引用 |
| AI 成本与隐私 | 用户流失 | 本地模型可选、发送前脱敏与预览、token 预算、完全可关闭 |
| 开放式主题的安全问题 | 主题变后门 | 主题是纯数据，禁止任意 JS，仅允许受限 CSS 变量 |
| 功能蔓延导致做不完 | 永远发布不了 | M0 只做 core + 周视图 + 提醒；插件与 AI **只预留接口不实现** |
| 商业化侵蚀体验（WakeUp 的教训） | 用户信任崩塌 | 本地优先 + 无广告承诺 + 数据可完整导出，把"可控"写进产品契约 |
